## Day 08：Experience / Guide UI

已实现场景选择、标题、一题一屏静态三问、上一题、跳过、空白和 3000 字输入。`sessionStorage` 只在当前标签页保存虚构演练草稿，刷新后恢复当前步骤、答案和候选状态；浏览器关闭、禁用存储或清除草稿后无法恢复。它不具备 owner 校验、跨设备同步或服务器持久化。

**Mock 替换记录：0 个真实接口已接入。** 当前远程分支尚无 B 的 Experience/Answer API 或共享 Contract，A 不把浏览器存储称为“问答系统完成”。待 B 提供接口后，A 可将读取/保存接到同一路径，使用 B 的真实版本号和错误码；不得沿用本页 `answer-local-*` 作为数据库 ID。

交 B 的请求与错误差异：

| 操作 | A 页面目前需要 | 等 B 明确 |
| --- | --- | --- |
| 建立经历 | `scene`、`title` → `experience_id` | 会话主体、owner_id、初始 version |

## Day 09：Fact Review UI

桌面宽屏左右并排展示原话和候选，窄屏顺序展示。每条候选有 `source_answer_id`、内容、归属（个人/团队/未知）、待核实/本人确认/已否定状态，并可返回原话修改。缺来源、无依据数字、头衔、奖项和“团队写成个人”触发醒目风险提示；这些是**前端关键词演练规则**，不是 C 的 Fact Validator，也不能证明语义识别完整。

内部浏览器自测（虚构数据）：加载样例后加入四条风险候选，四类提示均可见；安全候选可手动确认；改原话后旧确认失效；刷新后演练草稿与状态恢复；全空白问答后手工填入“获得 95 分”，无来源提示阻止确认。约 354 px 视口下页面 `scrollWidth=339`，未见横向溢出。真实设备、用户理解与剪贴板/导出链路不在本页验收范围。

交 B 的状态/版本问题：每个 Fact 应指向稳定的 `source_answer_id` 和来源 version；原话修改应由服务端将相关确认回退；仅服务端允许候选转 `user_confirmed`，并校验 owner、预期版本与跨用户访问。本页没有写入 API 或数据库，不能证明这些门禁已实现。

交 C 的用词案例：虚构原话“不记得分数”与候选“获得 95 分”；普通参与与候选“主导”；无奖项原话与候选“获得一等奖”；“小组获得课程成绩”被选为个人行动。C 需给出结构化风险码和解释文案，A 再把演练规则换成正式响应；未审样本不得进入 approved 回归集。
