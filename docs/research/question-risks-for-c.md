# Day 02｜A → C 问题措辞与风险样例（待评审）

状态：A 提交的风险候选；真实访谈样本 0，以下话语均为**虚构演练**，不是受访者原话。请 C 审核 [访谈提纲](interview-guide.md) 的六问、模型任务边界与 Eval 候选。

| 应避免的问法/表述 | 为什么有风险 | 中性问法或产品处理 |
| --- | --- | --- |
| “你是不是主导了这个项目？” | 暗示个人角色 | “你亲手做了哪些步骤？其他人做了什么？” |
| “效率是不是显著提升了？” | 诱导方向与程度 | “你怎么知道结果？有记录吗？没有也可以。” |
| “拿到奖项之后有什么收获？” | 预设获奖 | “这件事最后发生了什么？哪些部分不确定？” |
| “你帮助了多少人？” | 可能逼出猜测数字 | “是否知道具体人数？不知道就保留未知。” |
| “你肯定有跨文化沟通能力吧？” | 把能力标签塞给用户 | “当时和谁沟通？你具体说了或做了什么？” |
| “团队得 A，所以你取得 A” | 团队结果误归个人 | 原话、团队成果与个人行动并列，候选句只写可证实的个人部分 |
| “AI 已确认这个事实” | 模型不能确认真实经历 | AI 只能建议待核实项；确认由用户逐条操作 |

## 交给 C 的待答问题

1. 哪些提问即使看似开放，仍会暗示“好简历一定有数字/结果”？
2. Fact Extractor、Highlight、Rewrite 的输出如何保留未知和来源，避免“未知→0”或“团队→个人”？
3. 模型不可用时，静态问题与手动编辑如何让 P0 主流程继续？
4. 哪些强词必须触发用户复核，哪些应直接从无依据的候选句删除？

可用 S01/S02 作为**合成 Eval 输入候选**，正式 Eval 样本需另行标注来源和预期，不得将其称为真实采访。C 的审查结论应在自己的风险词文件或 PR 中回复；本文件不代替 C 签收。
